## 冰箱页点击「添加物品」需带入选中的区/层

**问题**：冰箱详情页（`pages/fridge`）点击某层内的「添加物品」后，`item-edit` 页总是默认选中第一个分区的第一层，没有继承冰箱页传来的 `zoneId`/`layerId`。

**根因**：`pages/item-edit/item-edit.ts` 的 `loadFridgeStructure()` 无论是否带参，都会把 `zoneId`/`layerId` 强制重置为第一个分区/层，覆盖掉 `onLoad` 从 options 写入的值。冰箱页的 `onAddItemFromLayer` 传参本身是正确的。

**修复**：在 `loadFridgeStructure()` 中，若 `this.data.zoneId` 已存在（来自冰箱页），则按 `zoneId` 定位分区索引、按 `layerId` 定位层索引，再回填 `zoneIndex/layerIndex/selectedZoneName/selectedLayerName/zoneId/layerId`；找不到时回退默认第一项。

**注意**：`pages/fridge/fridge.wxml` 的 `add-item-row` 绑定的是 `data-zone-id="{{item.zoneId}}"`（item 为 zone，命名易混淆），但传参已正确。

## 临期列表 / 冰箱页 swipe-cell 真机左滑失效（已修复）

**问题**：首页临期列表、冰箱页物品列表左滑删除，模拟器能滑出、真机滑不出来。

**真正根因（关键！）**：TDesign `t-swipe-cell` 的整套手势位移计算写在 `swipe-cell.wxs` 里，靠 **wxml 动态把 wxs 函数绑成事件处理器** 来驱动：
`bind:touchmove="{{skipMove ? '' : disabled || swipe.onDrag}}"`。
项目 `app.json` 配了 `"componentFramework": "glass-easel"`。在 glass-easel 真机 runtime 下，这种「wxs 函数做事件处理器」的机制**不生效** → `onDrag` 永不调用 → wrapper 位移从不更新 → 滑不出来。模拟器走另一套兼容层所以能滑。
> ⚠️ 曾误判为 scroll-view 嵌套冲突（去掉 scroll-view 后仍不行，由此排除）。scroll-view 改动保留（首页改用原生下拉刷新，无害），但不是左滑失效的根因。

**修复**：自写一个不依赖 wxs 的 `my-swipe-cell` 组件（`components/swipe-cell/`，用标准 methods 事件函数 + `createSelectorQuery` 量右侧宽度 + `bind:touchmove` 计算位移，纵向滑动放行给页面滚动）。
- `app.json` usingComponents 注册 `my-swipe-cell`（移除 `t-swipe-cell`）。
- `index.wxml`、`fridge.wxml` 所有 `<t-swipe-cell>` → `<my-swipe-cell>`，slot="right" 的删除按钮与原有 `onDeleteItem` / `onDeleteExpiringItem` 逻辑完全复用（slot 透传，点击由页面方法处理）。
- 组件用 `multipleSlots + addGlobalClass`，页面 `.swipe-delete` 样式照常生效。

**经验**：本项目用 glass-easel，凡是依赖 wxs 动态事件绑定的 TDesign 组件在真机都可能失效。遇到「模拟器能、真机不能」的手势/动画类问题，优先怀疑 glass-easel 与 wxs 事件绑定的兼容性，必要时用标准 methods 自写组件替代。

## 第三轮：补删除 toast + 还原 TDesign 下拉刷新

**现象**：用户确认 `my-swipe-cell` 左滑可用后，反馈①删除成功后无 toast；②想把 TDesign 下拉刷新加回来。

**toast 缺失根因**：`index.ts` 的 `onDeleteExpiringConfirm` 只调 `deleteItem` + `loadData`，全程无 `wx.showToast`。
**修复**：`.then` 内 `wx.showToast({title:'删除成功', icon:'success'})`，`.catch` 内 `wx.showToast({title:'删除失败', icon:'none'})`。

**加回下拉刷新**：因为真正根因是 wxs（非 scroll-view），`my-swipe-cell` 在 `t-pull-down-refresh` 内依旧可用。
- `index.wxml`：把上一轮改的 `<view wx:else class="page-body">` 还原为 `<t-pull-down-refresh wx:else value="{{refreshing}}" bind:refresh="onRefresh" loading-texts="{{['下拉刷新','松手刷新','正在刷新']}}">` + 内部 `<view class="page-body">`（保留底部留白）。
- `index.json`：移除 `enablePullDownRefresh/backgroundTextStyle/backgroundColor`（与 TDesign 刷新二选一，避免双触发）。
- `index.ts`：`onPullDownRefresh` → `onRefresh`，恢复 `refreshing` 状态（setData true→loadData→false）。
- `t-pull-down-refresh` 自身含 scroll-view（无需额外嵌套 scroll-view）。`my-swipe-cell` 用 `bind:touchmove`，纵向滑动放行、横向滑动处理，与竖向 scroll-view 不冲突（竖 scroll-view 不消费横向手势）。

**结论**：wxs-glass-easel 是左滑失效唯一根因的假设，在「my-swipe-cell + t-pull-down-refresh」结构下已得到验证（若真机再滑不出，则 scroll-view 也是因素，需给 my-swipe-cell 加 scroll-lock 事件）。

## 第四轮：左滑误触下拉 + 删除后骨架屏过渡

**问题①**：首页左滑物品时容易误触发 TDesign 下拉刷新（手势有轻微纵向分量时，列表在顶部会被判为下拉）。
**修复**：`t-pull-down-refresh` 有 `disabled` 属性。给 `my-swipe-cell` 增加 `lock` 事件——在 `onTouchMove` 判定为横向滑动的瞬间 `triggerEvent('lock',{locked:true})`，`onTouchEnd/Cancel` 时 `{locked:false}`。页面 `onSwipeLock` 把 `e.detail.locked` 写入 `swiping`，`t-pull-down-refresh disabled="{{swiping}}"`。这样左滑期间下拉被禁用，松手恢复。纵向滑动不锁（不放行滚动）。

**问题②**：删除成功后 `loadData()` 重新渲染，列表"突变"无过渡。
**修复**：删除走骨架屏过渡。新增 `listLoading` 状态；`onDeleteExpiringConfirm` 先 `setData({deleteVisible:false, listLoading:true})`，`deleteItem` 成功后 `await loadData()` 再 `listLoading:false`；`catch` 也置 `listLoading:false`。`index.wxml` 临期列表卡片条件改为 `expiringItems.length>0 || listLoading`：加载时渲染 3 行 `.skeleton-row`（CSS 灰条 + shimmer 动画），否则渲染真实 `my-swipe-cell` 列表。`index.wxss` 新增骨架屏样式。失败仍弹"删除失败"toast。

**经验**：TDesign `t-pull-down-refresh` 的 `disabled` 仅禁下拉手势、不影响滚动，是「列表内滑动操作 vs 下拉刷新」冲突的标准解法。

## 第五轮：整页骨架屏（首页）+ 冰箱结构骨架屏

**用户诉求**：删除/重载时不止临期列表，首页冰箱卡片、物品总数等数字也会"突跳/消失"，希望整页骨架屏过渡；冰箱管理页的列表也要骨架屏。

**修复（首页）**：
- 移除 `loading` 的 spinner 分支与局部 `listLoading` 方案，统一为 `pageLoading` 驱动的**整页骨架屏**。
- `app.wxss` 新增全局骨架屏公共样式（`.sk-block/.sk-emoji/.sk-line/.sk-tag/.sk-avatar/.sk-num/.sk-label/.sk-switch/.sk-banner/.sk-action/.sk-row` + `@keyframes sk-loading`），首页/冰箱页共用，并从 `index.wxss` 删掉重复定义。
- `index.wxml`：空状态条件改为 `!pageLoading && !hasFridge`；`<t-pull-down-refresh wx:else>` 内真实内容加 `wx:if="{{!pageLoading}}"`，并用 `wx:else` 整页骨架分支（冰箱卡片骨架 + 切换条 + 横幅 + 快捷按钮 + 临期列表 3 行）。

- 效果：删除/重载时**整页**（含冰箱卡片与统计数）变骨架，数据回来一次性切换，不再局部数字突跳。

**注意**：冰箱页 `onShow` 每次回页都会 `loadFridgeData()` 触发 `loading`，故每次从添加/编辑返回都会闪一下骨架（比原 spinner 体验好，但若想只在数据为空时显示骨架需另做判断）。

## 第七轮：fridge-settings 删除冰箱无 toast

**问题**：冰箱设置页点「删除冰箱」确认后，冰箱确实被删（回到列表），但不弹"删除成功"toast。

**根因**：`onDeleteConfirm` 用 TDesign 页面级 `Toast`（依赖 `<t-toast id="t-toast"/>` 实例，实例本身存在）。但代码在 `Toast(...)` 显示后**同步**调用 `wx.navigateBack({delta:2})` 立即卸载本页面，TDesign Toast 的页面级组件实例随之被销毁，toast 渲染被中断 → 看不到。首页删除物品用系统级 `wx.showToast` 跨页面存活，所以正常。

**修复**：
- `fridge-settings.ts`：移除 `import Toast from 'tdesign-miniprogram/toast'`；`onDeleteConfirm` 改 `wx.showToast({title:'删除成功',icon:'success'})`，`catch` 补 `wx.showToast({title:'删除失败',icon:'none'})`；成功提示后用 `setTimeout(...,600)` 延迟再 `navigateBack`，让 toast 停留可见。
- `fridge-settings.wxml`：删除已无用的 `<t-toast id="t-toast" />`。

**经验**：在会 `navigateBack` 关闭自身的页面里，提示必须用系统级 `wx.showToast`（或延迟返回），不能用 TDesign 页内 `Toast`（页面卸载即销毁）。

## 第八轮：mine 页冰箱列表避免每次切回都刷新

**诉求**："我的"页每次进/切回都重新加载冰箱列表（闪骨架），希望只在首次加载、以及新增/删除/编辑冰箱后才刷新。

**机制**：`app.globalData.homeDataDirty` 已由 `fridge-create.onSave`、`fridge-settings.onDeleteConfirm`（删除）、`item-detail`（增删物品）、`member-manage`（成员变更）、`scan-result`（扫码加入）等置 `true`，作为"数据已变更"标记；消费点（置 false）在 index.ts 与 mine.ts。全项目 grep 确认无"持续置 true"的隐藏点。

**第一次修复（未根治）**：在 `mine.ts` 用页面 data `fridgesLoaded` 标志判断。但实测切回仍闪——根因是 tab 页切回时**页面实例可能被销毁重建**，`data` 重置回 `fridgesLoaded:false`，于是每次都走刷新分支。

**第二次修复（根治）**：把"已加载"标志移到**常驻的 `globalData.fridgesReady`**（`app.ts` 新增 `fridgesReady:false`），跨页面销毁不丢：
- `mine.ts` `onShow` 判断改为 `if (!app.globalData.fridgesReady || app.globalData.homeDataDirty) loadData()`。
- `loadData` 成功后置 `app.globalData.fridgesReady = true`（成功/catch 都设），并清 `homeDataDirty`。
- 移除页面 data 的 `fridgesLoaded` 字段。
- 效果：首次进闪骨架；之后单纯切 Tab 不闪（globalData 标志常驻）；新增/删除冰箱后切回 mine 才刷新闪骨架。

**第九轮（第八轮引入的回归 bug）**：第八轮在 `loadData` 加了 `if (this.data.fridgesLoading) return` 做防重入守卫，但 `data.fridgesLoading` 初始就是 `true`，导致**首次 onShow 调用 loadData 时守卫立即 return、一次都没真正拉数据、`fridgesLoading` 永不置 false** → 骨架屏永远卡住、无数据。用户反馈"现在一直是骨架屏，没数据"。

**修复**：防重入守卫改用**独立的实例属性** `self._fridgeLoading`（初始 undefined/假，不在 data 里），`finally` 中复位。绝不能用 `data.fridgesLoading`（初始 true）做守卫，否则会挡掉首次加载。

**经验**：① tabBar 页"是否已加载"标志放 `全局 globalData` 而非页面 data；②**防重入守卫绝不能用初始为 true 的 loading 状态字段本身**——会挡掉首次加载，正确做法是单独用一个初始 falsy 的实例/模块级标志。
