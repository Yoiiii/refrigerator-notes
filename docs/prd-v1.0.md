# 📄 PRD：冰箱笔记小程序（v1.1）

## 一、产品概述

### 1.1 产品定位

一款面向家庭的冰箱食品管理工具，帮助用户记录存放物品及其保质期，避免食物过期浪费。支持多人协作管理同一台冰箱，通过二维码分享实现家庭成员间的便捷共享。

### 1.2 目标用户

- 家庭主妇/主夫、合租室友、单身独居青年
- 注重食材新鲜度、希望减少浪费的人群

### 1.3 核心价值

- 减少食物浪费
- 提升冰箱空间管理效率
- 家庭协同管理，信息透明

### 1.4 设计语言

- UI 框架：**TDesign Weixin**（组件路径：`tdesign-miniprogram/xxx/xxx`）
- 视觉风格：温暖家居风（主色 `#FF9F45`，背景 `#FAF8F5`，大圆角卡片）
- 交互原则：流畅、即时反馈、低学习成本

## 二、信息架构（新增）

### 2.1 数据实体关系

```
User (微信用户)
  └─ 拥有多个 Fridge （通过 user_fridge 关联表）
       └─ 每个 Fridge 有多个 Item
       └─ 每个 Fridge 可被多个 User 访问（不同权限）

user_fridge 关联表：
  - userId: string        // 用户 openid
  - fridgeId: string      // 冰箱 ID
  - role: 'owner' | 'readonly' | 'readwrite'
  - joinedAt: timestamp
```

### 2.2 页面树（新增“分享”相关页面/弹窗）

```
首页 (index)
 ├─ 创建冰箱 → 冰箱创建页 (fridgeCreate)
 └─ 已有冰箱 → 冰箱详情页 (fridgeDetail)
      ├─ 物品列表（展开层）
      ├─ 添加物品 (addItem)
      ├─ 冰箱设置 (fridgeSettings) ← 新增
      │    ├─ 编辑冰箱信息
      │    ├─ 成员管理（查看/移除成员）
      │    └─ 分享冰箱（生成二维码） ← 新增
      └─ 扫码加入 → 扫码结果处理页（scanResult）
```

## 三、功能需求详述

### 3.1 用户与冰箱关联（新增）

#### 3.1.1 用户首次登录

- 调用 `wx.login` 获取 openid，存入本地缓存及云数据库 `users` 集合。
- 查询 `user_fridge` 表获取该用户的所有冰箱列表（含角色）。

#### 3.1.2 创建冰箱

- 创建成功后，自动向 `user_fridge` 表插入一条记录，`role: 'owner'`。
- 用户默认为冰箱的“所有者”，拥有最高权限（可删除冰箱、管理成员、修改冰箱结构）。

#### 3.1.3 加入冰箱（扫码）

- 用户扫描二维码后，解析得到 `fridgeId`。
- 检查该用户是否已有关联记录：
  - 若已存在，提示“已在冰箱中”。
  - 若不存在，弹出确认弹窗：“是否加入 [冰箱名称]？你将获得 [只读/可读写] 权限。”
- 确认后写入 `user_fridge` 表，刷新冰箱列表。

### 3.2 冰箱分享（新增）

#### 3.2.1 生成分享二维码

- 入口：冰箱详情页右上角菜单 → “分享冰箱”
- 操作步骤：
  1. 用户选择分享权限（只读 / 可读写）。
  2. 调用云函数生成带参数的二维码（`scene=fridgeId&role=readonly`）。
  3. 展示二维码图片，并提供“保存到相册”按钮。
- 二维码有效期：7天（可配置），过期后需重新生成。

#### 3.2.2 权限说明

- **只读**：可查看冰箱结构、物品列表、保质期状态，不可添加/修改/删除物品，不可修改冰箱设置。
- **可读写**：拥有除“管理成员”和“删除冰箱”之外的全部操作权限（添加/修改/删除物品、修改冰箱名称等）。
- **所有者**：唯一拥有全部权限，包括转让所有权、移除成员、删除冰箱。

#### 3.2.3 成员管理

- 入口：冰箱设置页 → 成员管理
- 展示所有成员的头像、昵称、角色。
- 所有者可：
  - 更改成员角色（只读 ↔ 可读写）
  - 移除成员（被移除者不再能看到该冰箱）
  - 转让所有权（需对方确认）

### 3.3 原有功能（保持不变，仅补充权限校验）

所有涉及数据变更的操作（添加物品、修改物品、删除物品、修改冰箱结构）均需校验当前用户在 `user_fridge` 表中的 `role`：

- 只读用户：按钮置灰，点击提示“暂无编辑权限”。
- 可读写/所有者：正常操作。

## 四、交互与体验规范

### 4.1 流畅性要求

- 页面切换耗时 ≤ 300ms（可使用 `wx.navigateTo` 预加载）。
- 列表滑动帧率 ≥ 50fps，避免长列表卡顿（使用 `recycle-view` 或分页加载）。

### 4.2 状态反馈（补充分享相关）

| 场景                      | 反馈方式                             | 组件        |
| ------------------------- | ------------------------------------ | ----------- |
| 生成二维码中              | 全屏加载遮罩 + 文案“正在生成分享码…” | `t-loading` |
| 二维码生成成功            | 显示二维码图片 + 底部按钮            | —           |
| 二维码生成失败            | 错误提示弹窗                         | `t-dialog`  |
| 扫码加入中                | 加载遮罩 + “正在验证…”               | `t-loading` |
| 扫码加入成功              | 顶部 Toast “已成功加入冰箱”          | `t-toast`   |
| 扫码加入失败（重复/无效） | 错误提示                             | `t-dialog`  |
| 权限不足操作              | 轻提示“暂无编辑权限”                 | `t-message` |

### 4.3 空状态与异常

- 用户未加入任何冰箱时，首页显示“创建第一个冰箱”引导卡片（同原有）。
- 扫码后 fridgeId 不存在或已被删除：提示“冰箱已失效”。

## 五、非功能需求

### 5.1 性能

- 冰箱列表、物品列表数据量预估 ≤ 500 条/冰箱，采用云数据库查询 + 本地缓存。
- 二维码图片大小控制在 200KB 以内。

### 5.2 安全

- 二维码中的 `fridgeId` 使用云函数生成的带签名字段，防止篡改。
- 所有数据操作均通过云函数鉴权（校验 `openid` 与 `role`）。
- 用户敏感信息（openid）仅在后端使用，前端不存储明文。

### 5.3 兼容性

- 基础库版本 ≥ 2.25.0（支持 `wx.scanCode` 和云开发）。
- TDesign 组件版本 ≥ 1.3.0。

## 七、AI 代码生成提示词建议

请在生成代码时严格遵守以下约束：

1. **组件引用**：所有 TDesign 组件必须在对应页面的 `.json` 文件中声明 `usingComponents`，路径为 `tdesign-miniprogram/组件名/组件名`。
2. **数据模型**：使用以下 JSON 结构定义 `user_fridge` 集合：
   ```json
   {
     "_id": "自动",
     "userId": "string",
     "fridgeId": "string",
     "role": "owner | readonly | readwrite",
     "joinedAt": "timestamp"
   }
   ```
3. **权限校验**：在每个涉及写操作的云函数开头，查询 `user_fridge` 表判断 `role`，若非 `owner` 或 `readwrite` 则返回错误。
4. **二维码生成**：使用云函数 `generateQRCode`，内部调用 `wx.cloud.callFunction` 的 `getWXACodeUnlimit` 接口，参数 `scene` 编码 `fridgeId_role`，`page` 设为 `pages/scanResult/scanResult`。
5. **扫码处理**：`scanResult` 页面接收 `scene` 参数，解码后检查 `user_fridge` 表，若无记录则弹出加入确认弹窗。
6. **视觉风格**：主色 `#FF9F45`，背景 `#FAF8F5`，卡片圆角 `24rpx`，按钮圆角 `16rpx`，冰箱层用大圆角渐变背景。
